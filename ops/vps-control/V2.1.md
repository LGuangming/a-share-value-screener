# VPS Control Bridge V2.1 — separate asynchronous workers

The installed V1 status connection and all V2 report tools remain compatible.
Wire title/schema stay VPS CONTROL v1 / ashare-vps-control-v1; capabilities
returns bridge_version 3 for the V2.1 implementation. New execution profiles
are disabled by default. No inbound network endpoint, Docker socket, sudo,
arbitrary shell or automatic deployment.

## Architecture and restrictions

The non-root ashare-control service authenticates private GitHub issues as
before. It durably commits a job identity to local state, then publishes one
fixed profile request in a lane-specific local spool. It returns to polling
GitHub and can answer read-only status/report requests while a worker runs.
Only one remote execution job may be outstanding across both lanes. New
execution requests remain unaccepted while busy; they may expire after
15 minutes. A queued job's original accepted identity is retained even after
the issue becomes old; do not edit or reopen accepted task issues.

Independent services:
- ashare-research: no network (PrivateNetwork=yes), 1 CPU, 1 GiB, no
  GitHub or Tushare credential. Runs only locally approved offline profiles.
- ashare-collection: official Tushare HTTPS capture, 0.5 CPU, 512 MiB,
  separate UID and Tushare systemd credential, no GitHub credential.
  Only fixed collect-reference and collect-dividend wrappers are permitted.

Each lane has a bridge-owned request directory (worker read-only) and
worker-owned result directory (bridge read-only). Setgid group + file mode
0640 permit cross-service read access only in the relevant lane. Systemd
hardening and ReadWritePaths limit writes to approved locations.
The bridge never receives Tushare Token. Collection subprocesses receive it
only from the local collection worker. The root-owned runtime/scripts must
be independently reviewed; no untrusted code or user-controlled arguments.

Each worker writes a running receipt before starting a task, then a final
receipt. On interruption a running receipt becomes interrupted_unknown_do_not_retry.
Never automatically re-execute an interrupted issue. If GitHub is unreachable
delivery resumes separately from execution. Preserve all queue and bridge state;
do not delete receipts to retry. Final issue results contain only status,
profile alias, elapsed seconds and exit code. Task status can show queued or
running while execution is underway; detailed per-month progress is not yet
automatically exported. Local report ACLs must be explicitly configured.
One worker's successful exit does not prove actual data coverage or strategy
validity. Profile and systemd timeouts still apply; no continuous multi-day job.

## Install, but do not enable

Review the exact accepted commit and full CI first. From the separate
/opt/ashare-control-source checkout, as local administrator:

    python3 -m unittest discover -s ops/vps-control -p 'test_*.py' -v
    bash ops/vps-control/upgrade-v2.sh
    bash ops/vps-control/install-async.sh

The scripts pause polling, preserve existing GitHub token/state/config and
install separate systemd units/accounts and spool directories. The second
script requires setfacl (ACL utilities). It does NOT grant access to backtest
data or enable new workers. Do not install in a running job; pause timers
and wait for existing jobs to finish before upgrading. Existing v1/v2
configuration can be used without enabling the asynchronous worker lanes.

After reviewing the bridge config, restart only the bridge first and check
capabilities:

    systemctl start ashare-vps-control.service
    systemctl enable --now ashare-vps-control.timer

    {"schema":"ashare-vps-control-v1","task":"capabilities"}

No need to create another GitHub repository or PAT.

## Research worker setup

Complete V2.md's reviewed research.json and accepted Python/backend/data
prerequisites. Change research.json ownership to root:ashare-control-research
and mode 0640, grant the ashare-research UID only read/traverse access to
required immutable source/data/evidence paths. Do not grant Docker or sudo.
The asynchronous runner stores results in /var/lib/ashare-research-work,
not the old /var/lib/ashare-control-work. Use a new run_name for any changes.
Configure /etc/ashare-control/research-worker.json with the actual private
task repository numeric ID and only locally approved profiles, e.g.:

    {
      "repository_id":0,
      "profiles":{
        "bt05-preflight":{"script":"/opt/ashare-control/profiles/bt05-preflight","timeout_seconds":1800}
      }
    }

The zero ID must be replaced; it deliberately fails validation. Enable
additional fixed bt05-signals, bt05-portfolio and bt05-walk wrappers only after
their prerequisites are accepted. Add to existing bridge config.json:

    "async_profiles":{"bt05-preflight":"research"}

Remove any matching alias from synchronous profiles (duplicate routes rejected).
Do not overwrite existing identities, inventory or reports. For remote read-only
report snapshots, configure exact approved aliases pointing to the new work
directory, and selectively grant ashare-control read/traverse ACLs to the
specific outputs (including future atomic replacement files where necessary).
Do not expose the entire worker state or runtime directory; the bridge filters
report fields but must be able to read approved files.

    systemctl start ashare-research-worker.service
    systemctl enable --now ashare-research-worker.timer

Remote execution:
    {"schema":"ashare-vps-control-v1","task":"run_profile","profile":"bt05-preflight"}
    {"schema":"ashare-vps-control-v1","task":"task_status"}

## Collection worker setup (optional, separately authorized)

First ensure the accepted runtime contains BT05 reference/dividend capture
modules. Copy collection.example.json to /etc/ashare-control/collection.json,
replace example paths and dates, owner root:ashare-control-collection mode
0640. Dates and API budgets are fixed by the local administrator. Dividend
capture requires the real independently reviewed calendar JSON (read-only);
reference capture can start with calendar=null. The worker writes raw receipts
only inside /var/lib/ashare-collection-work/reference and dividend.
Use selective read ACLs for reconciliation; never publish raw data to GitHub.

Local budgets: reference 1..30, dividend 1..50 requests per invocation, total
1..100 reserved requests per China calendar day, configurable downward.
Reserve the full request budget durably before attempting calls; no refund
if some requests were skipped/reused or task interrupted. This is intentionally
conservative. It covers only this worker, NOT all other Tushare jobs. Coordinate
account-wide quotas and avoid overlapping existing provider tasks.
Only official endpoint, no relay fallback. Start with one request, inspect
actual receipt before larger capture; account access and real coverage
remain unverified.

Create root-only /etc/ashare-control/tushare-token (0600) using secure local
input; never paste it in chat or GitHub, never put it in config.json.
Set /etc/ashare-control/collection-worker.json to actual private repo numeric
ID and approved capture wrappers. Example:

    {
      "repository_id":0,
      "profiles":{
        "collect-reference":{"script":"/opt/ashare-control/profiles/collect-reference","timeout_seconds":600}
      }
    }

Add collect-reference:collection to async_profiles in bridge config.
Do not enable collect-dividend until calendar review and data access.
Only after local approvals:

    systemctl start ashare-collection-worker.service
    systemctl enable --now ashare-collection-worker.timer

Remote:
    {"schema":"ashare-vps-control-v1","task":"run_profile","profile":"collect-reference"}

The worker suppresses raw provider output to avoid credential disclosure;
inspect locally produced receipts and separately run BT05 audit/review.
No automatic review, trading, new permissions, production writes or live
historical returns from this bridge.

## Acceptance

Offline tests cover queued execution, concurrent diagnostic while queued,
single-job restriction, no duplicate worker execution, interruption, pinned
identity, fixed commands and daily budget. Real systemd permissions, resource
limits, worker restart/recovery and provider entitlement must be validated
on the VPS. Do not claim live asynchronous execution before an accepted real
test. Stop timers to disable new requests; stopping an active worker may
leave an interrupted unknown task. Preserve state and inspect local results
before resubmitting. No auto-update or remote privilege escalation.
